# План реализации

Работаем по одному этапу: план → подтверждение → реализация → отчёт. В конце каждого этапа: `pnpm lint && pnpm typecheck && pnpm test` без ошибок, короткий отчёт «что сделано / что проверить руками», коммит (по согласованию).

## M0 — Каркас

- Next.js 16 + React 19 + TS strict + Tailwind v4 + ESLint/Prettier, pnpm
- `docker-compose.yml` для разработки: PostgreSQL 17
- Drizzle: схема по `docs/schema.sql`, первая миграция
- Токены светлой и тёмной темы, шрифты из DESIGN.md, базовый layout с `TopNav` / `BottomTabBar`
- Каркас бота (`bot/`): grammY, запуск отдельной командой, подписанный клиент к `/api/bot/*` (пока только health)
- GitHub Actions: lint, typecheck, test на каждый push
- `.env.example`, `README.md` с запуском за 3 команды
- Seed: только демо-данные (семестр «Осень 2026» с 31.08, сетка звонков МГТУ, группы 11М/12М, вымышленные предметы и преподаватели)
- **Готово, когда:** `docker compose up -d && pnpm db:migrate && pnpm db:seed && pnpm dev` показывает пустой каркас с навигацией в обеих темах, CI зелёный.

## M1 — Вход и доступ

- Вход через бота (deep link + poll), сессии в БД на 400 дней со скользящим продлением
- Проверка участия в чате, выбор группы, экраны «нет доступа» / «группа не подключена»
- QR-вход на другом устройстве, ссылка для входа от админа
- Guards `requireMember`, `requireRole`; dev-вход в development
- Бот запускается локально (long polling, с VPN) — домен для этого этапа не нужен
- **Готово, когда:** вход через тестового бота работает, сессия переживает перезапуск браузера, роли проверяются на сервере, есть тесты подписи bot-API и сессий.

## M2 — Расписание (ядро)

- `lib/schedule/resolve.ts` + все тесты из DATA_MODEL.md (сначала тесты)

## M3 — Деплой

Можно сдвинуть раньше, как только будут домен и сервер.

- Тест доступности: временный VPS, проверка с МТС/Билайн/МегаФон/Т2 и домашнего интернета → выбор: один сервер в Европе или сайт в РФ + бот в Европе
- Dockerfile (standalone), сборка образов в GitHub Actions → GHCR, compose для прода (app, postgres, bot, caddy), Caddy с HTTPS
- Бэкапы: `pg_dump` + файлы → restic во внешнее хранилище, раз в сутки, хранение 14 дней; проверка восстановления
- Healthcheck-эндпоинт, логи
- **Готово, когда:** сайт открывается по домену у всей группы, вход работает, бэкап восстановлен на чистой машине.

## M4 — Конспекты и материалы

- Пайплайн приёма `lib/ingest/` (sharp: EXIF, HEIC, 2560/480 webp; файлы до 50 МБ), отдача с проверкой сессии
- Загрузка с сайта (к паре или в материалы), прогресс
- Библиотека по макету Library: «Занятия» и «Материалы», lightbox, фильтры, поиск
- Лимиты и rate limit
- **Готово, когда:** студент с телефона загружает 10 фото к прошедшей паре, они видны всем в библиотеке, EXIF удалён.

## M7 — Темы ✅

- Список с фото напечатанного листа (OCR), из Excel или по строкам; подтемы; вместимость 1 / 2 / команда
- Сначала присутствующие (код и QR с экрана старосты, меняются каждые 30 с), потом «для всех» — кнопкой или по времени
- Запись атомарно, одна тема на человека, ФИО один раз (правится в профиле и админке)
- Очередь сдачи, «сдано», ручная запись, выгрузка в Excel и текстом для чата, «Выступают» на «Сегодня»
- Объявление в чат при открытии и напоминания — в M6

## M8 — Задания и рубежки ✅

- Домашние задания: срок «к следующей паре» по умолчанию (или к дате), переезд вместе с перенесённой парой, личная отметка «сделано»
- Контрольные: на паре или в своё время, «что будет», «можно / нельзя», допуск, материалы для подготовки, своя страница
- Материалы: файлы библиотеки со страницей, конспекты занятий, ссылки; загрузка прямо из формы
- Раздел «Задания» (вместо «Рубежек»), метки на парах в «Сегодня» и «Неделе», блок «Скоро»
- Напоминания в Telegram — в M6
