# «пара.» — сайт учебной группы

Сайт для магистерской группы (информационная безопасность): актуальное расписание с отменами, заменами и переносами, выбор тем и очередь сдачи, расписание рубежных контролей, библиотека фото-конспектов по парам и новости от старост. Заменяет разрозненные сообщения в Telegram. Telegram остаётся каналом уведомлений: бот дублирует туда то, что староста публикует на сайте.

Пользователей мало (одна группа, ~20–30 человек). Сайт должен быть простым, быстрым на телефоне и дешёвым в поддержке. Не усложнять архитектуру ради масштаба, которого не будет.

## Документы — читать перед работой
- `docs/SPEC.md` — что делаем: роли, разделы, сценарии, критерии готовности
- `docs/DATA_MODEL.md` и `docs/schema.sql` — модель данных и логика расписания
- `docs/DESIGN.md` — токены, шрифты, цвета статусов, компоненты
- `docs/ROADMAP.md` — этапы; работаем строго по одному этапу за раз
- `design/*.dc.html` — согласованные макеты (HTML-разметка; открывать как референс, не как код для копирования — там свой рантайм)

## Стек
- Next.js 15 (App Router, Server Components, Server Actions), TypeScript strict
- Tailwind CSS v4, токены из `docs/DESIGN.md` в `@theme`
- PostgreSQL 16 + Drizzle ORM (миграции через drizzle-kit)
- Хранилище файлов: S3-совместимое (MinIO локально и на сервере), доступ через `@aws-sdk/client-s3`
- Обработка фото: `sharp` (ресайз, превью, webp, удаление EXIF)
- Авторизация: Telegram Login Widget → проверка подписи на сервере → своя сессия (httpOnly cookie, `iron-session` или `jose`)
- Telegram-бот: `grammY`, в том же репозитории (`bot/`), общий слой БД
- Даты: `date-fns` + `date-fns-tz`, часовой пояс всегда `Europe/Moscow`
- Валидация: `zod` на всех входах (формы, server actions, API)
- Деплой: Docker Compose на своём VPS (app + postgres + minio + bot), reverse proxy Caddy

## Команды (настроить на этапе M0)
- `pnpm dev` — разработка
- `pnpm db:generate` / `pnpm db:migrate` — миграции
- `pnpm db:seed` — тестовые данные (расписание, предметы, темы из макетов)
- `pnpm lint`, `pnpm typecheck`, `pnpm test` (vitest)
- `docker compose up -d` — postgres + minio локально

## Структура
```
app/                 маршруты (RU-интерфейс)
  (app)/today, week, topics, exams, library, news
  (staff)/manage/... панель старосты
  api/auth/telegram  callback логина
lib/
  db/                схема drizzle, клиент, запросы
  schedule/          разрешение расписания (база + изменения) — чистые функции, покрыты тестами
  auth/              сессия, проверка Telegram hash, guards по ролям
  storage/           S3, sharp-пайплайн
  telegram/          отправка сообщений ботом
components/          UI по DESIGN.md
bot/                 grammY-бот
docs/, design/       ТЗ и макеты
```

## Правила
- Интерфейс полностью на русском. Код, имена переменных, коммиты — на английском.
- Все проверки прав — на сервере (server actions / route handlers), не только скрытием кнопок. Роли: `student`, `starosta`, `admin`.
- Любой вход валидируется zod. Никакого сырого SQL с конкатенацией.
- Фото с пар: при загрузке удалять EXIF (в т.ч. геолокацию), делать превью 480px и полноразмер ≤2560px в webp; лимит 15 МБ на файл.
- Логика «какие пары в этот день» живёт только в `lib/schedule/` и покрыта unit-тестами (чётность недель, отмена, замена, перенос, разовая пара).
- Mobile-first: каждый экран сначала проверять на ширине 390px. Тач-цели ≥44px.
- Секреты только через env (`.env.example` держать актуальным). Токен бота и секрет сессии никогда не логировать.
- Перед завершением этапа: `pnpm lint && pnpm typecheck && pnpm test` без ошибок.
- Не добавлять зависимости без необходимости; если добавляешь — коротко объясни зачем.
