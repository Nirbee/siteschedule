# «пара.» — сайт учебных групп ИУ8-11М и ИУ8-12М

Сайт для магистратуры МГТУ им. Баумана (кафедра ИУ8, информационная безопасность): актуальное расписание с отменами, заменами и переносами, выбор тем и очередь сдачи, рубежные контроли, библиотека фото-конспектов и материалов (с импортом и автосортировкой из Telegram-чата) и новости от старост. Telegram остаётся каналом уведомлений: бот дублирует туда то, что публикуется на сайте, и сам забирает фото из чата.

Пользователей мало (2 группы по ~20–30 человек, позже, возможно, ещё 1–2). Сайт должен быть простым, быстрым на телефоне и дешёвым в поддержке. Не усложнять архитектуру ради масштаба, которого не будет. Возможное мобильное приложение в будущем — поэтому логика в `lib/`, а не в компонентах.

## Документы — читать перед работой

- `docs/SPEC.md` — что делаем: группы, роли, вход, разделы, бот, открытые вопросы
- `docs/DATA_MODEL.md` и `docs/schema.sql` — модель данных, логика расписания, вход, API бота, автосортировка
- `docs/DESIGN.md` — токены (светлая и тёмная тема), шрифты, цвета статусов, компоненты
- `docs/ROADMAP.md` — этапы; работаем строго по одному этапу за раз
- `design/*.dc.html` — согласованные макеты (референс, не код для копирования; там свой рантайм)

## Стек

- Next.js 16 (App Router, Server Components, Server Actions), React 19, TypeScript strict
- Tailwind CSS v4, токены из `docs/DESIGN.md` в `@theme` + CSS-переменные для тёмной темы
- PostgreSQL 17 + Drizzle ORM (миграции через drizzle-kit). После M0 источник истины по схеме — `lib/db/schema.ts`
- Файлы: локальный диск (`STORAGE_DIR`, Docker volume) через `lib/storage/`; отдача через route handler с проверкой сессии
- Обработка фото: `sharp` (поворот, удаление EXIF, 2560/480 webp, HEIC), не больше 2 задач одновременно
- Вход: через Telegram-бота (deep link + poll), сессии в БД, cookie на 400 дней со скользящим продлением
- Telegram-бот: `grammY`, long polling, в этом же репозитории (`bot/`), отдельный процесс. **Без доступа к БД** — только подписанный HTTP API сайта (`/api/bot/*`)
- Даты: `date-fns` v4 + `@date-fns/tz`, часовой пояс всегда `Europe/Moscow`
- Валидация: `zod` на всех входах (формы, server actions, API, ответы для бота)
- Тесты: vitest
- Деплой: Docker Compose (app + postgres + bot + caddy), образы собираются в GitHub Actions → GHCR, reverse proxy Caddy

## Команды (настраиваются на M0)

- `pnpm dev` — сайт; `pnpm bot:dev` — бот
- `pnpm db:generate` / `pnpm db:migrate` — миграции
- `pnpm db:seed` — демо-данные
- `pnpm schedule:import data/private/schedule.json` — загрузить реальное базовое расписание (повторный запуск обновляет)
- `pnpm import:tg <папка>` — импорт экспорта Telegram Desktop (M5)
- `pnpm lint`, `pnpm typecheck`, `pnpm test`
- `docker compose up -d` — postgres локально

## Правила

- Интерфейс полностью на русском. Код, имена переменных, коммиты — на английском.
- **Репозиторий публичный.** Никаких реальных данных (расписание, ФИО, Telegram ID, экспорты чата, фото) и секретов в git. Seed — только демо-данные. Реальные данные — через админку или файлы в `data/private/` (в `.gitignore`).
- Все проверки прав — на сервере (server actions / route handlers), не только скрытием кнопок. Роли: `student`, `starosta`, `admin`.
- Server actions — тонкая обёртка над `lib/services/`; бизнес-логику в компонентах и actions не писать.
- `bot/` не импортирует `lib/db` и сервисы (ограничено правилом ESLint `no-restricted-imports`).
- Любой вход валидируется zod. Никакого сырого SQL с конкатенацией.
- Фото: удалять EXIF (в т.ч. геолокацию), превью 480px и полноразмер ≤2560px в webp; лимит 15 МБ на фото, 50 МБ на файл.
- Логика «какие пары в этот день» живёт только в `lib/schedule/` и покрыта unit-тестами (числитель/знаменатель, группы, отмена, замена, перенос, разовая пара, «другое время»). Правила автосортировки в `lib/ingest/` — тоже.
- Цвета только через семантические токены; каждый экран проверять в светлой и тёмной теме.
- Mobile-first: каждый экран сначала проверять на ширине 390px. Тач-цели ≥44px.
- Секреты только через env (`.env.example` держать актуальным). Токен бота, `BOT_API_SECRET`, токены сессий никогда не логировать.
- Перед завершением этапа: `pnpm lint && pnpm typecheck && pnpm test` без ошибок.
- Коммиты и push — только по согласованию с пользователем.
- Не добавлять зависимости без необходимости; если добавляешь — коротко объясни зачем.
